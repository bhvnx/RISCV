# RV32I Single-Cycle Processor

A single-cycle RISC-V base integer (RV32I) processor implemented in SystemVerilog.  
Simulated with **Verilator 5** and verified against **Spike** (RISC-V ISA reference simulator) using constrained-random tests generated by **riscv-dv**.

---

## Design Overview

The processor uses a **Harvard memory model** — separate instruction and data memories — and a **single-cycle execution model** where every instruction completes in one clock cycle.

The reset vector is `0x80000000`, matching Spike's DRAM base so that PC values in simulation logs can be compared directly.

### Modules

| Module           | Description                                                                 |
|------------------|-----------------------------------------------------------------------------|
| `riscv_core`     | Top level — wires all submodules together                                   |
| `control_unit`   | Decodes opcode / funct3 / funct7 into control signals                       |
| `alu`            | Arithmetic and logic unit (ADD, SUB, AND, OR, XOR, shifts, SLT/SLTU)       |
| `reg_file`       | 32 × 32-bit integer register file; x0 hardwired to zero                     |
| `instr_mem`      | Combinational read-only instruction memory; loaded from hex at sim start    |
| `data_mem`       | Synchronous data memory with byte/halfword/word access                      |
| `imm_gen`        | Sign-extends immediates for I / S / B / U / J formats                      |
| `pc_incrementer` | Computes PC + 4                                                             |

### Supported Instructions

All RV32I base integer instructions:

- **R-type** — ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU
- **I-type** — ADDI, ANDI, ORI, XORI, SLLI, SRLI, SRAI, SLTI, SLTIU, LW, LH, LB, LHU, LBU, JALR
- **S-type** — SW, SH, SB
- **B-type** — BEQ, BNE, BLT, BGE, BLTU, BGEU
- **U-type** — LUI, AUIPC
- **J-type** — JAL
- **System** — ECALL (halt sentinel), CSR instructions (return 0 for all CSR reads)

## Verification

The verification strategy is **ISS co-simulation**: the same test program runs on both the RTL (via Verilator) and **Spike** (the official RISC-V ISA reference simulator). Both produce a **commit log** — one line per retired instruction recording PC, encoding, destination register, and written value — which are then compared instruction-by-instruction.

Test programs are generated automatically by **riscv-dv**, a constrained-random instruction generator that produces legal RV32I programs covering arithmetic, shifts, loads, stores, branches, and jumps.

### Verification Flow

```
  verif/tests.yaml
  (test names + iteration counts)
        │
        │  make gen  or  make fullregress
        ▼
  ┌─────────────┐
  │  riscv-dv   │  constrained-random RV32I assembly generator
  │  (pyflow)   │
  └──────┬──────┘
         │  .S files  →  verif/logs/_gen_<test>/asm_test/
         ▼
  ┌──────────────────┐
  │  compile_test.py │  riscv64-unknown-elf-as + ld + objcopy
  └────────┬─────────┘
           │
           ├─── instr_mem.hex  (Verilog $readmemh format, @20000000 base)
           │
           └─── test.elf
                   │
        ┌──────────┴──────────────────────────────────┐
        ▼                                             ▼
  ┌───────────┐                              ┌──────────────┐
  │   Spike   │  ISA reference simulator     │  run_spike.py│
  │ --isa=rv32i                              └──────┬───────┘
  │ --log-commits                                   │
  └───────────┘                                     │
        │                                           ▼
        │                              spike_parsed.json
        │                              (golden commit log)
        │
        │  make regress  or  make fullregress
        ▼
  ┌─────────────────────────────────────────────────┐
  │  Makefile regress target                        │
  │                                                 │
  │  for each verif/logs/riscv_*_test_N/:           │
  │    1. extract code section from instr_mem.hex   │
  │       (awk: keep first @address block only,     │
  │        rebase to @00000000)                     │
  │    2. write to .regress_active.hex              │
  │    3. run Verilator DUT simulation              │
  │       → verif/logs/<test>/dut.log               │
  │    4. compare_logs.py  PASS / FAIL              │
  └─────────────────────────────────────────────────┘
        │
        ▼
  === Regression complete: N passed, M failed ===
```

### Make Targets

| Command | What it does |
|---|---|
| `make sim` | Compiles RTL with Verilator (builds `obj_dir/Vriscv_core_tb`) |
| `make run` | Runs the hand-written smoke test (`sw/test_basic.s`), prints register/memory checks |
| `make gen` | Reads `verif/tests.yaml`, generates new tests via riscv-dv, compiles them, runs Spike |
| `make regress` | Simulates all existing test folders against the DUT, compares with Spike golden logs |
| `make fullregress` | `gen` then `regress` — full flow in one command |
| `make clean` | Removes Verilator build output |

### Configuring Tests

Edit `verif/tests.yaml` to control which tests are generated and how many random seeds:

```yaml
tests:
  - name: riscv_arithmetic_basic_test
    iterations: 10
  - name: riscv_rand_instr_test
    iterations: 5
```

Available riscv-dv test names for RV32I:

| Test name | Coverage |
|---|---|
| `riscv_arithmetic_basic_test` | ADD/SUB/AND/OR/XOR/SLL/SRL/SRA + immediates |
| `riscv_rand_instr_test` | Fully random mix of all instructions |
| `riscv_jump_stress_test` | Heavy JAL/JALR/branch sequences |
| `riscv_loop_test` | Loops with branches |

Each run of `make gen` adds new test folders numbered from the next available index — existing folders are never overwritten. Run `make regress` as many times as you like; it only refreshes `dut.log` in each folder.

### Running the Full Automated Regression

```bash
# From inside WSL, at the project root:

# One-shot: generate new tests AND simulate all of them
make fullregress

# Or separately:
make gen        # generate + compile + spike  (slow — riscv-dv runs for ~1 min per test)
make regress    # simulate all existing tests against DUT  (fast — seconds per test)
```

Example output:

```

[PASS] 11036 instruction(s) match

=== verif/logs/riscv_arithmetic_basic_test_1 ===
[PASS] 9444 instruction(s) match

```

### Smoke Test (single hand-written program)

```bash
# Build and run the hand-written test_basic.s (from project root, WSL)
make run

# Run Spike on the same program
python3 verif/scripts/run_spike.py sw/test_basic.elf --outdir verif/logs

# Compare
python3 verif/scripts/compare_logs.py verif/logs/spike_parsed.json verif/logs/dut.log
```

### Commit Log Format

Every retired instruction is logged as one line:

```
PC=0x80000000 INSTR=0x00500093 RD=x1 VAL=0x00000005
PC=0x80000004 INSTR=0x00300113 RD=x2 VAL=0x00000003
PC=0x80000008 INSTR=0x002081b3 RD=x3 VAL=0x00000008
```

Writes to x0 are suppressed (x0 is hardwired to zero — no architectural effect). `compare_logs.py` checks PC, instruction encoding, destination register, and written value for every committed instruction.

### Address Space

Both DUT and Spike execute starting at `0x80000000`:

| | Spike | DUT |
|---|---|---|
| Reset / entry | MROM boot → jump to `0x80000000` | `pc_q <= 32'h8000_0000` |
| Hex base address | `@20000000` (word address) | rebased to `@00000000` by awk in Makefile |
| Memory index | DRAM at `0x80000000` | `mem[pc[16:2]]` → `mem[0]` |

The Makefile's `regress` target extracts only the first section of each riscv-dv hex file (the executable code) and rebases it to `@00000000` before loading. Subsequent zero-filled BSS/data sections are dropped — those regions are accessed by the program via LOAD/STORE through `data_mem`.

### Tools

| Tool | Role |
|---|---|
| `riscv64-unknown-elf-as` / `ld` | Assembles and links test programs to ELF at `0x80000000` |
| `riscv64-unknown-elf-objcopy` | Converts ELF → Verilog hex for `$readmemh` |
| **Spike** (`riscv-isa-sim`) | Official RISC-V ISA reference; produces golden commit log |
| **Verilator 5** | Compiles RTL to a cycle-accurate C++ simulation |
| **riscv-dv** (pyflow) | Constrained-random RV32I test generator |
| `verif/scripts/gen_test.py` | Invokes riscv-dv to generate random `.S` programs |
| `verif/scripts/compile_test.py` | Assembles `.S` → ELF + `instr_mem.hex` |
| `verif/scripts/gen_all.py` | Reads `tests.yaml`, orchestrates gen + compile + Spike |
| `verif/scripts/run_spike.py` | Runs Spike, parses `--log-commits` output to JSON |
| `verif/scripts/compare_logs.py` | Diffs DUT log against Spike JSON line-by-line |
